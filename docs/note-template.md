State the problem in one or two paragraphs. Say what is true, what fails, and why a reader should care. Name the concrete system or incident. Do not open with a heading.

## Example

Walk one case in order. Prefer a short program, a sequence of events, or a failing request over a general claim. Number the steps that the later sections refer back to.

> **Note**
>
> A callout is for a distinction the main paragraph would bury. One distinction per callout.

## What causes it

Name the conditions that have to be true at the same time. A single condition is not the bug.

## Determinations

Say what to do. Each determination is something a reader can apply without rereading the note. If a tempting fix does not work, say so in its own subsection and explain the failure.

## Open questions

What is still unsettled. Leave this section out only when nothing is unsettled, and then say that in Determinations.
